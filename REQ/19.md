# R-#19: Scripts prep-vm-ia multi-VM

Scripts `prep-vm-ia-anfitrion` y `prep-vm-ia-invitado` para crear una o
más máquinas virtuales que corran simultáneamente con IAs aisladas pero
compartiendo `/var/www/adJ-ia/` vía NFS del anfitrión.

---

**Created:** 2026-08-05
**Status:** En progreso

## Motivación

La máquina anfitrión tiene suficiente RAM para 3 o más VMs de desarrollo,
una por proyecto (ej: `adJ`, `adJ-port`, `m-dev`), todas compartiendo
`/var/www/adJ-ia/` vía NFS.

## Comportamiento de vmd con `local interface`

Cada `local interface` declarada en `/etc/vm.conf` asigna una subred
`/24` independiente según el **orden de declaración**:

| # en vm.conf | Subred | Host IP | VM IP |
|-------------|--------|---------|-------|
| 1ª VM | `100.64.1.0/24` | `100.64.1.1` | `100.64.1.2` |
| 2ª VM | `100.64.2.0/24` | `100.64.2.1` | `100.64.2.2` |
| 3ª VM | `100.64.3.0/24` | `100.64.3.1` | `100.64.3.2` |

- Las VMs **no se ven entre sí** (subredes aisladas).
- Todas las VMs **ven al anfitrión** en `100.64.N.1`.
- Si se arranca una VM con `vmctl start` que no está en `vm.conf`,
  vmd le asigna un ID después del último en `vm.conf` (ej: si hay
  5 VMs declaradas, la dinámica usa ID 6 → `100.64.6.0/24`).
- NFS debe exportarse para todo el rango: `-network=100.64 -mask=255.255.0.0`.

## Diseño

### `prep-vm-ia-anfitrion [nombre] [memoria]`

**Interfaz:**
```sh
doas ./prep-vm-ia-anfitrion adJ-port 12G      # interactivo (dialog)
doas ./prep-vm-ia-anfitrion -auto adJ-port 12G # no interactivo
```

**Modo interactivo (sin `-auto`):**
- Muestra cada hallazgo y pide confirmación con `dialog` o `read -p`
- Pregunta antes de sobrescribir `install.conf`
- Pregunta antes de arrancar autoinstalación
- Nunca borra discos qcow2 existentes

**Modo automático (`-auto`):**
- Sin preguntas, usa defaults
- Sobrescribe `install.conf` sin preguntar
- Arranca autoinstalación sin confirmar
- Nunca borra discos qcow2 existentes

**Sin argumentos:** usa `VM_NOMBRE` del ambiente o genera nombre automático.

**Infraestructura común (1 sola vez, idempotente):**

1. NFS: `echo "${NFS_PATH} -alldirs -network=100.64 -mask=255.255.0.0" >> /etc/exports`
2. IP forwarding: `net.inet.ip.forwarding=1`
3. nginx: servir `install.conf` y `template.disklabel` desde `/var/www/htdocs/`
4. vmd: `rcctl enable vmd`

**Por VM (idempotente):**

1. Determinar nombre: `$1` o auto-generado (`adJ-iaN`)
2. Disco: `/var/vmm/${nombre}.qcow2`
3. Si el disco no existe:
   - `vmctl create -s ${VM_TAMDISCO} ${VM_DISCO}`
   - Generar `install.conf` para nginx con nombre, IP (`100.64.N.2`), usuario
   - Generar `template.disklabel`
   - `vmctl start -B cdrom -r ${ISO} -d ${VM_DISCO} ${nombre}`
   - Esperar/verificar instalación (disco creció)
4. Agregar entrada en `/etc/vm.conf` (si no existe):
   ```
   vm "${nombre}" {
     memory ${VM_MEMORIA}
     disk "${VM_DISCO}" format qcow2
     local interface
   }
   ```
5. Arrancar VM desde disco si no está corriendo

**Variables de ambiente:**

| Variable | Defecto | Descripción |
|----------|---------|-------------|
| `VM_MEMORIA` | `12G` | RAM por VM |
| `VM_TAMDISCO` | `50G` | Tamaño de disco |
| `VM_USUARIO` | `whoami` | Usuario inicial en la VM |
| `ISO_PATH` | auto-detección | Ruta a la ISO de adJ |
| `ZONA_HORARIA` | `America/Bogota` | Zona horaria |
| `NFS_PATH` | `/var/www` | Directorio exportado |

**Pendientes:**
- [ ] `install.conf` necesita la IP correcta (`100.64.N.2`) ¿cómo saber N
  antes de declarar en `vm.conf`? Opciones:
  - a) Determinar N = (líneas `vm "` en vm.conf) + 1
  - b) La VM usa DHCP o `100.64.1.2` temporal y luego se reconfigura
- [ ] La autoinstalación necesita que el anfitrión tenga IP en la subred
  de la VM — pero `local interface` la asigna automáticamente

### `prep-vm-ia-invitado`

**Red: automática.** vmd incluye un servidor DHCP interno para
`local interface`. La VM obtiene su IP (`100.64.N.3`) y ruta por
defecto (`100.64.N.1`) sin configuración manual de `vio0`.
No se requiere bloque `[red]` en el script.

**`NFS_SERVER` automático:** el anfitrión siempre es el gateway:
```sh
NFS_SERVER="${NFS_SERVER:-$(route -n get default 2>/dev/null | awk '/gateway/ {print $2}')}"
NFS_SERVER="${NFS_SERVER:-100.64.1.1}"
```
Así cada VM detecta `100.64.N.1` como su NFS_SERVER sin intervención manual.

## Esquema de red real (vmd DHCP interno)

```
Anfitrión
  ├── 100.64.1.1 ──── VM adJ-ia     (100.64.1.3)  — desarrollo adJ
  ├── 100.64.2.1 ──── VM adJ-port   (100.64.2.3)  — compilación portes
  └── 100.64.3.1 ──── VM m-dev      (100.64.3.3)  — desarrollo m
       │
       └── NFS export: 100.64.0.0/16 → /var/www
```

VMs aisladas entre sí. Solo ven al anfitrión vía `100.64.N.1`.
Comparten `/var/www` vía NFS.

extrayéndolo desde la base de datos de SIVeL 2.2 con las herramientas de

## Motivación

El tarball incluido en `7.9p1-amd64/sivel/nocheyniebla2001-2015-xrlt.tar.gz`
tiene 51 558 relatos en formato XRLAT (XML, DTD `SINCODH relatos 0.97`) del
Banco de Datos del CINEP. El nombre miente en el extremo inferior: los hechos
más antiguos que contiene son de **1968** (y hay tres anteriores a 1910), no de
2001. El extremo superior sí es correcto: no hay un solo registro posterior a
**2015**.

La base de desarrollo `sivel2gen_des` (cargada desde `sivel2-todo-13.sql`)
tiene **48 187 casos** con fechas de **1999-07-01 a 2026-06-30**, sin nulos. Es
decir, la base vigente arranca donde el tarball apenas empieza y se extiende 11
años más. **El nuevo tarball se genera enteramente desde esta base**; los
archivos del tarball anterior no se reutilizan.

`<relato>` de un caso. Probado con el caso 872:

```ruby

c.set_response!(ActionDispatch::Response.new)
c.instance_variable_set(:@caso, Sivel2Gen::Caso.find(872))
```

Produce `<relato><organizacion_responsable>Banco de Datos del CINEP</...>` con
`<id_relato>872</id_relato>`, `<forma_compartir>publico</forma_compartir>` y el
resto de campos, **idéntico en estructura al tarball de 2015**. Notas:

- Hay que ejecutar dentro de `sivel2-2.2` con `PATH=/usr/local/bin:$PATH`

## Diseño propuesto

1. **Generar un `.xrlat` por caso desde la base 2.2.** Script
   `bin/rails runner` (en `sivel2-2.2/scripts/`) que recorra
   `Sivel2Gen::Caso.find_each`, renderice el partial `_caso.xrlat` para cada uno
   y escriba `nyn<id>.xrlat` envuelto en `<relatos>` con el `DOCTYPE` 0.99.
2. **Verificar el saneamiento.** La base `sivel2gen_des` ya pasó por
   `scripts/elimina_datos_privados.rb`: 1 usuario (`adminexp`), 0 bitácoras, 0
   anexos, 0 fuentes de prensa, 0 etiquetas de caso. El script de exportación
   debe **abortar** si detecta alguna de esas tablas con filas, para no publicar
   datos privados por error.
3. **Envolver cada relato.** Cada archivo lleva su propio `<?xml ...?>`,
   `<!DOCTYPE relatos SYSTEM ".../relatos-099.dtd">` y un `<relatos>` con un solo
   `<relato>` adentro. El `DOCTYPE` de salida es **0.99**, el que emite el
   builder actual y que `importar_relato` acepta.
4. **Empaquetar.** `tar -czf nocheyniebla<ini>-<fin>-xrlt.tar.gz` con los
   `.xrlat` en la raíz del archivo (como el actual: `./nynNNN.xrlat`).
5. **Validar.** Reimportar una muestra con `importar_relato` en un SIVeL 2.2 de
   prueba y comprobar que el número de casos importados coincide con el esperado
   y que no hay etiquetas `ERROR_IMPORTACIÓN`.
6. **Renombrar y publicar.** Colocar el tarball en `7.9p1-amd64/sivel/` con el
   rango de años real, eliminar el `2001-2015`, y actualizar la nota de
   `Contenido.txt` si menciona años.

## Decisiones tomadas (2026-11-15)

1. **Rango en el nombre:** `nocheyniebla1999-2026-xrlt.tar.gz` (primer y último
   año con hechos en la base).
2. **Alcance:** los 48 187 casos completos, sin recorte.
3. **Saneamiento:** la base `sivel2gen_des` ya está saneada; el script aborta si
   detecta bitácoras, anexos, fuentes de prensa o etiquetas de caso.
4. **DTD de salida:** 0.99.
5. **Reproducibilidad:** script `sivel2-2.2/scripts/exporta_nocheyniebla.rb`.

## Implementación

`/var/www/adJ-ia/sivel2-2.2/scripts/exporta_nocheyniebla.rb`, ejecutado con:

```sh
cd sivel2-2.2
PATH=/usr/local/bin:$PATH bin/rails runner -e development \
  scripts/exporta_nocheyniebla.rb /tmp/nyn_export
```

Qué hace:

- Verifica que la base esté saneada y **aborta** si encuentra datos privados.
- Localiza el DTD `relatos-099.dtd` dentro de la gema `sivel2_gen` instalada.
- Recorre `SELECT id FROM sivel2_gen_caso ORDER BY id`, renderiza
  `sivel2_gen/casos/_caso` en formato `:xrlat` con un `Sivel2Gen::CasosController`
  instanciado a mano (`set_request!`/`set_response!`/`@caso`), y valida cada
  relato contra el DTD 0.99 antes de escribirlo.
- Escribe `nyn<id>.xrlat`; los inválidos van a `errores.txt` y no al tar.
- Deriva el rango de años de `MIN`/`MAX` de `sivel2_gen_caso.fecha` y empaqueta
  con `tar -czf ... -C <dir> .` (OpenBSD `tar` no tiene `-T`, y archivar el
  directorio evita el límite de argumentos con 48 187 rutas).
- El `.tar.gz` se crea **fuera** del directorio exportado para no incluirse a sí
  mismo.

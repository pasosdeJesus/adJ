# R-#18: Script `m` (wrapper) para @pasosdejesus/m (instalación local, rápido)

Crear un script `m` ligero que instale el CLI `@pasosdejesus/m` en un
directorio local y lo ejecute directo con `node`, evitando la sobrecarga de
`npx` en cada invocación. Se mantiene actualizado con un chequeo por TTL
cuando hay Internet y funciona sin red usando la copia instalada.

---

**Created:** 2026-08-05
**Status:** Pendiente

## Prioridad

Se prefiere un script ligero en lugar de un porte OpenBSD. La primera versión
usaba `npx @pasosdejesus/m@latest`, pero el arranque quedaba lento (~3.6 s)
porque `npx` resuelve `@latest` contra el registro en cada invocación (y el
wrapper lo hacía dos veces). Se cambió a:

- Instalar `@pasosdejesus/m` en `$M_DIR` (por defecto `~/.m-cli`) con `npm
  install --prefix`.
- Ejecutar `node $M_DIR/node_modules/@pasosdejesus/m/dist/m.js` directo
  (~0.7 s, el costo de arranque del propio CLI).
- Actualizar a `@latest` solo si pasaron `M_TTL` segundos (por defecto 86400
  = 1 día) desde la última actualización, y solo si hay conexión.

Así queda corto (`m`), rápido (~0.7 s), actualizado online y funcional
offline, sin el mantenimiento de un porte.

## Lógica del script

```sh
#!/bin/sh
M_DIR="${M_DIR:-$HOME/.m-cli}"
M_BIN="$M_DIR/node_modules/@pasosdejesus/m/dist/m.js"
M_STAMP="$M_DIR/.actualizado"
M_TTL="${M_TTL:-86400}"

# Detectar node/npm: el paquete node de OpenBSD incluye ambos
if ! command -v node >/dev/null 2>&1 || ! command -v npm >/dev/null 2>&1; then
  echo "m: se requiere el paquete node (incluye npm): doas pkg_add node" >&2
  exit 1
fi

instala() {
  npm install --prefix "$M_DIR" --no-fund --no-audit \
    @pasosdejesus/m@latest >/dev/null 2>&1
}

if [ ! -f "$M_BIN" ]; then
  if ! instala; then
    echo "m: no se pudo instalar @pasosdejesus/m (¿sin conexión?)" >&2
    exit 1
  fi
  date +%s > "$M_STAMP"
fi

ahora=$(date +%s)
ultimo=$(cat "$M_STAMP" 2>/dev/null || echo 0)
if [ "$M_TTL" = "0" ] || [ $((ahora - ultimo)) -ge "$M_TTL" ]; then
  if instala; then
    date +%s > "$M_STAMP"
  fi
fi

exec node "$M_BIN" "$@"
```

### Robustez del wrapper

1. **Tormenta de reintentos sin red.** El sello `$M_STAMP` sólo se escribe cuando `instala` tiene
   éxito; sin conexión, cada invocación vuelve a llamar a `npm` (y espera). Agregar un sello de
   *intento* con espera (`M_RETRY=3600`) y `npm --prefer-offline --fetch-timeout=3000`.
2. **Actualización no atómica.** `npm install` reescribe `dist/` mientras otra invocación ejecuta
   `node "$M_BIN"`. Instalar en `$M_DIR/versions/<v>` y conmutar el symlink `current` (o instalar en
   `$M_DIR.tmp` y `mv`).
3. **Concurrencia.** Dos `m` simultáneos se pisan: lock con `mkdir "$M_DIR/.lock"` (OpenBSD base no
   tiene `flock`), liberado con `trap`/`rmdir`.
4. **Cadena de suministro.** `@latest` ejecuta código nuevo cada TTL: `--ignore-scripts` es seguro
   (el `postinstall` de `m` sólo imprime) y conviene `M_VERSION` para fijar (`M_VERSION='^0.32'`) en
   imágenes reproducibles.
5. **Diagnóstico.** Hoy todo va a `/dev/null`; guardar el último error en `$M_DIR/.last-error` y
   mostrarlo cuando falla la instalación inicial (hoy sólo dice "¿sin conexión?").
6. **Alcance.** `loadPlugins()` lee el `package.json` del consumidor (`cwd`, `..`, `../..`): dentro
   de un proyecto aparecen `mpdj` y los motores; fuera, sólo los comandos núcleo. Documentarlo.

### Preseed offline (sugerido)

El primer uso **exige red**. Para una imagen adJ conviene llevar el CLI ya instalado:

- Copia en `/usr/local/share/m/node_modules/@pasosdejesus/m` y `M_DIR=/usr/local/share/m` por
  defecto cuando exista; el wrapper sólo actualiza si hay red y el usuario lo mantiene en `~/.m-cli`.
- Alternativa: un paquete de adJ (`m-cli`) con la copia y `M_TTL=0` por defecto; el wrapper queda
  para el usuario que quiera `@latest`.
- En ambos casos, `instala` debe seguir siendo el camino cuando falta la copia (equipos sin preseed).

### Manual (`man m`) generado por el CLI

`man m` como página escrita a mano se desincroniza del CLI. Propuesta: un subcomando `m man`
(también `m --man`) que **genere mdoc** (`.Dd`, `.Dt`, `.Sh`, `.Op`, `.Fl`, `.Cm`, `.Xr`) a partir del
**mismo registro** que produce `--help` (categorías + `commands`), y que:

- `mandoc -Tlint m.1` pase sin avisos (verificación en CI);
- se instale en `man/man1/m.1` del paquete npm y en `/usr/local/man/man1/m.1` en adJ;
- el wrapper lo regenere al instalar/actualizar (una línea, sin red adicional).

### pnpm: adJ no lo trae por omisión

`m:create` (desde `0.32.0`) genera un **workspace con `pnpm@11.28.6`** y `m` no debe asumir que
existe:

- el wrapper (o `m:create`) debe **detectar `pnpm`** y, si falta, explicar cómo instalarlo
  (`npm i -g pnpm@11` o `doas pkg_add` si adJ lo empaqueta) en vez de fallar dentro de `pnpm -r`;
- `m:check` ya reporta el `packageManager` del proyecto; conviene que además avise cuando la versión
  de pnpm instalada no coincide;
- documentar en el manual de adJ que un proyecto nuevo requiere pnpm (red o paquete).

### Nombre

`m` no se usa en adJ: no hay colisión. Si algún día se empaqueta, usar el mismo nombre del binario.

### Paquete de OpenBSD vs `npx`

- **`npx` no**: resuelve `@latest` contra el registro en cada invocación (~3.6 s medido). Sirve para
  probar, no para uso diario.
- **`npm install -g @pasosdejesus/m`**: lo natural para usuarios de Node; cero mantenimiento de
  puertos.
- **Paquete/porte de OpenBSD**: tiene sentido para adJ y para quien no use npm a diario. Es viable:
  el CLI es **JS puro** (sin binarios nativos) y sus dependencias son cuatro (`dotenv`, `execa`,
  `glob`, `picocolors`). El porte requiere construir **sin red**: empaquetar los tarballs de npm como
  `DISTFILES`/`MASTER_SITES` locales y hacer `npm ci --offline` en `do-build`, instalar en
  `/usr/local/lib/node_modules/@pasosdejesus/m`, symlink `/usr/local/bin/m` y la página `m.1`.
  `PERMIT_PACKAGE=Yes`, `MODULES=lang/node` (o el módulo equivalente de la versión actual).
- **Recomendación:** mantener npm como canal principal y **enviar el porte cuando `m` esté estable**
  (después de `0.32.0` y con la migración a pnpm 11 cerrada), para no rehacerlo con cada release.
  Mientras tanto, el preseed en adJ cubre el caso sin red.

## Semántica de ejecución con `/usr/local/bin/m`

Como el wrapper ejecuta **su propia** copia (`node "$M_DIR/…/dist/m.js"`), hoy el `m` que corre
siempre es el global/preseed; del proyecto sólo se cargan **plugins y motores** (`loadPlugins()` lee
`cwd`, `..`, `../..` y `loadEnginePackages()` importa desde el `node_modules` del consumidor).

Propuesta: **gana el `m` del proyecto cuando exista**, que es la convención de Node y lo que hace
reproducible el `pnpm-lock.yaml`. El global queda como respaldo (y como base del preseed offline).

| Caso | Dónde está `m` | Qué ejecuta | Aviso |
|---|---|---|---|
| **A. Proyecto sin `m`** | no hay `node_modules/@pasosdejesus/m` | copia **global** (preseed/`~/.m-cli`) | ninguno |
| **B. Proyecto con `m`, misma versión** | local == global | copia **local** | ninguno |
| **C. Proyecto con `m`, otra versión** | local != global | copia **local** | una línea a stderr: `m: usando m@X del proyecto (global m@Y); M_GLOBAL=1 para forzar` |
| **D. Local declarado sin `dist/`** (`link:` a fuente sin compilar) | local incompleto | **global** | `[WARN] m local sin dist; usando el global` |
| **E. La orden no existe en el local** | local | local (falla la orden) | error con pista: `probá M_GLOBAL=1 o actualizá m del proyecto` |

**Búsqueda (en el wrapper, POSIX sh), en orden:**

1. `M_GLOBAL=1` → copia global, sin más.
2. `$PWD/node_modules/@pasosdejesus/m/dist/m.js` y subiendo hasta 3 niveles (raíz del proyecto).
3. `$PWD/apps/*/node_modules/@pasosdejesus/m/dist/m.js` (layout con workspace).
4. Si ninguno existe → global (instala/actualiza según TTL).

**Reglas adicionales**

- **No modificar el proyecto:** el wrapper nunca instala ni toca `node_modules` del consumidor.
- **Plugins siempre del proyecto** (ya es así): al correr el global dentro de un proyecto, un plugin
  puede esperar una API más nueva; por eso avisa el caso C. Si la importación del plugin falla hoy
  en silencio, conviene que el wrapper lo muestre al menos con `M_DEBUG=1`.
- **`apps/web/bin/m` sigue siendo el del proyecto** y es el que usan los `Makefile`; `/usr/local/bin/m`
  es para las personas. Así una receta `make test` no cambia según lo que tenga el usuario instalado.
- **Preseed:** el global se actualiza por TTL sólo cuando se usa el global (casos A/D); si el
  proyecto trae su `m`, no hay descarga ni chequeo de red.
- **Caso C y adJ:** si el proyecto pide `pnpm@11` y adJ no lo trae, el aviso de versión de `pnpm`
  (`REQ/57` de `m`) es el que guía al usuario; el wrapper no instala pnpm.

### Implementación sugerida en el wrapper (precedencia del `m` del proyecto)

```sh
# 1. m del proyecto: node_modules junto al cwd, hasta 3 niveles, y apps/*/ en workspace
encuentra_local() {
  d=$(pwd)
  i=0
  while [ $i -le 3 ]; do
    [ -f "$d/node_modules/@pasosdejesus/m/dist/m.js" ] && { echo "$d/node_modules/@pasosdejesus/m/dist/m.js"; return 0; }
    for f in "$d"/apps/*/node_modules/@pasosdejesus/m/dist/m.js; do
      [ -f "$f" ] && { echo "$f"; return 0; }
    done
    d=$(dirname "$d"); i=$((i + 1))
  done
  return 1
}

if [ "${M_GLOBAL:-0}" != "1" ] && LOCAL=$(encuentra_local); then
  # aviso sólo si difiere de la versión global
  lv=$(node "$LOCAL" --version 2>/dev/null)
  gv=$(node "$M_BIN" --version 2>/dev/null)
  [ "$lv" != "$gv" ] && echo "m: usando $lv del proyecto (global $gv); M_GLOBAL=1 para forzar" >&2
  exec node "$LOCAL" "$@"
fi
# 2. si no hay local: instalar/actualizar por TTL y ejecutar $M_BIN (con el backoff de M_RETRY)
exec node "$M_BIN" "$@"
```

Detalles:

- `M_GLOBAL=1` desactiva la búsqueda local (escape cuando el `m` del proyecto está roto).
- La versión se compara una vez por invocación (dos `node --version`, ~40 ms) sólo si hay local.
- Si `encuentra_local` devuelve una ruta sin `dist/m.js` (p. ej. `link:` a fuente sin compilar) se
  trata como "sin local" y se avisa; así el caso D no rompe la ejecución.
- El preseed/TTL sólo se usa en los casos A/D; con `m` local no hay red ni descarga.
- `M_DEBUG=1` puede mostrar la ruta elegida, útil para soporte.

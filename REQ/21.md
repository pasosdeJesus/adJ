# R-#21: Automatizar pruebas con qemu

Automatizar la instalación desatendida y la verificación post-instalación de
adJ en QEMU (consola serial), sin pantalla, para cumplir la lista de
verificación del lanzamiento.

---

**Created:** 2026-11-03
**Issue:** https://gitlab.com/pasosdeJesus/adJ/-/work_items/21
**Status:** En progreso — script `hdes/qemu-autoinstall.py` escrito; falta
probar con disco de 30G y ampliar la verificación.

## Motivación

La publicación de una versión exige probar la imagen de instalación
(`GESTIÓN-DE-UNA-NUEVA-VERSION.md` §11): `uname` debe reportar
`APRENDIENDODEJESUS`, `vmstat -s` debe mostrar `servicio` (renombre de
`daemon`) y debe existir `/var/log/servicio`.

El camino natural es `prep-vm-ia-anfitrion` (vmd), pero el agente corre en una
VM invitada de `vmd` (`dmesg` muestra `OpenBSD VMM Host`) y `vmm(4)` no permite
anidación (`hw.vmm` no existe). Por eso la verificación usa QEMU con TCG.

Hacerlo a mano es lento y propenso a error. Se busca un script reproducible
que: instale desatendidamente y corra las pruebas de la lista de verificación.

## Diseño

Script `hdes/qemu-autoinstall.py` (Python, por el manejo de pty/consola
serial/servidor HTTP). Flujo:

1. **ISO temporal con consola serial** — respalda `etc/boot.conf`, le antepone
   `set tty com0`, regenera un ISO con `mkhybrid` y restaura `boot.conf`.
2. **Disco virtual** — `qemu-img create -f raw virtual.raw 30G`.
3. **Autoinstalación** — arranca QEMU (`-machine q35`, `-nographic`, CD primero),
   sirve `install.conf` por HTTP en `10.0.2.2:8000`, selecciona
   `(A)utoinstall` y entrega la URL del archivo de respuestas.
4. **Reinicio y verificación** — espera el `login:`, entra como root y ejecuta:
   `uname -a`, `vmstat -s | grep -i servicio`, `ls -d /var/log/servicio` y la
   prueba de locale de libc (`1.000.000,200000`).

Uso: `doas python3 hdes/qemu-autoinstall.py [tamano_disco_en_G]` (por omisión
30G). Requiere `qemu-system-x86_64`, `qemu-img` y `mkhybrid`.

## Rationale (decisiones)

### Consola serial con `set tty com0`

El bootloader de adJ usa `pc0` (VGA) por defecto en QEMU; solo cambia a `com0`
si detecta el hipervisor VMM (`machdep.c` compara el CPUID 0x40000000 con
`OpenBSDVMM58`). Con `-nographic` QEMU solo redirige la BIOS (int10) a la
serial: se ve el bootloader pero no el kernel.

Alternativas descartadas:

- **`-cpu max,hv-vendor-id=OpenBSDVMM58`**: no funciona en TCG (es una
  iluminación KVM); el kernel sigue en VGA.
- **QMP `input-send-event` para sostener Ctrl** (saltar `boot.conf` y entrar al
  prompt `boot>`): no funcionó; `check_skip_conf()` lee `pc_getshifts()` vía
  int16 AH=02 y la tecla inyectada no se reflejó.

Lo confiable es el `set tty com0` en `boot.conf` (documentado en
`boot(8)`: "Use serial console: `boot> set tty com0`"). Se hace en un ISO
temporal y se restaura, sin tocar el artefacto de release.

### `-machine q35` (SATA/AHCI)

Con `i440fx` + CD IDE, el kernel RAMDISK hizo panic durante la extracción de
`comp79.tgz` (`wdc_atapi_start: not ready, st = 50` → `trap type 4`). q35 usa
el driver `ahci` (no `wdc`) y evita el panic; además el disco pasa a `sd0`
(no `wd0`).

### Disco de 30G

Con auto-layout en 15G, `/usr` quedó lleno y falló `reorder_kernel`
(`/mnt/usr: write failed, file system is full`), por lo que no se creó el
kernel único. 30G debería dar espacio suficiente. (vmd ya lo evita con una
plantilla `disklabel` de 38G y disco de 50G.)

### Archivo de respuestas sin acentos

El instalador adJ elimina acentos al traducir (`tminiroot/conv.sh`). Las
claves deben ir sin acentos ni `¿`, p. ej. `Nombre de la maquina`,
`Clave para root`, `Cual es el disco raiz`, `Zona horaria`. Las preguntas con
valor por defecto seguro (red, sshd, X, etc.) pueden omitirse.

### `Continuar en todo caso = si`

`BUILDINFO` no está en `7.9-amd64/SHA256`, así que al final el instalador
pregunta `Suma de verificacion de BUILDINFO fallo. Continuar en todo caso?`.
Se responde `si` (junto con `Continuar sin verificacion = si`).

## Hallazgos para la publicación

- **BUILDINFO sin checksum**: corregido. `distribucion.sh` (línea ~1549)
  regenera el `SHA256` con `cksum -a sha256 $l` y su lista omitía `BUILDINFO`;
  se añadió `BUILDINFO` a la lista antes de generar `SHA256.sig`.
- **Disco mínimo**: con auto-layout, 15G es insuficiente para `/usr` durante
  el relink del kernel; recomendar ≥ 30G o una plantilla `disklabel` propia.
